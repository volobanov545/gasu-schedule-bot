# Запуск расписания через GitHub Actions

Сервер и постоянно включённый компьютер не нужны. Целевая схема запускает получение
публичного расписания в российском CI, а GitHub обновляет календарь в теме
Telegram. База данных, входящие сообщения, участники, файлы и AI не используются.

Основной рабочий ритм по Москве: GitVerse проверяет сайт **каждые 15 минут с 07:00 до
20:45 с понедельника по субботу**. Окно начинается за два часа до самой ранней пары
в 09:00 и покрывает четвертьчасовые границы занятий и напоминаний. Время до пары
рассчитывается на момент фактического выполнения, а не планового запуска CI.
В воскресенье выполняются три проверки — в 09:00, 15:00 и 21:00. Одна
двухнедельная карточка редактируется на месте и по возможности тихо закрепляется; новые
сообщения появляются только при изменении, для вечернего обзора и для напоминания.

## Что добавить в GitHub

Открой репозиторий → **Settings → Secrets and variables → Actions → New repository
secret** и создай четыре секрета:

| Secret | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен отдельного бота из BotFather |
| `TARGET_CHAT_ID` | отрицательный технический ID Telegram-группы |
| `SCHEDULE_TOPIC_ID` | положительный ID темы «Расписание» |
| `SPBGASU_GROUP_ID` | обозначение/ID учебной группы, которое принимает публичное расписание |

Не присылай токен в чат и не добавляй его в файлы репозитория. Бот должен быть добавлен
в группу и иметь право отправлять сообщения в нужную тему; администратором ему быть не
обязательно.

## Первый запуск

1. В GitVerse открой workflow **Fetch SPbGASU schedule and hand off to GitHub**.
2. Для обычной проверки оставь оба переключателя выключенными: сообщение придёт только
   при реальном изменении или в вечернее окно.
3. Для одной ручной карточки включи `force_digest`; до 20:00 МСК карточка показывает
   сегодня, после 20:00 — завтра.
4. `probe_schema` используется только для обезличенной диагностики парсера и ничего не
   передаёт в Telegram.

Старый прямой workflow GitHub удалён: зарубежный GitHub-hosted runner не может надёжно
подключиться к российскому источнику. Получение выполняет GitVerse, GitHub только
проверяет снимок, хранит состояние и отправляет сообщение. Принудительная карточка
одновременно создаёт чистый baseline и не выдаёт все занятия за ложные «добавления».

## Настройка CI-моста

1. Создай приватный репозиторий GitVerse и загрузи в него этот код.
2. В GitHub создай fine-grained personal access token только для репозитория
   `gasu-schedule-bot`, сроком на 90 дней и с единственным изменённым разрешением
   **Actions: Read and write**. GitHub также автоматически оставляет обязательное
   **Metadata: Read-only**; для импорта репозитория в GitVerse было добавлено
   **Contents: Read-only**.
3. В GitVerse открой **Настройки → Секреты и переменные** и добавь секрет
   `BRIDGE_GH_TOKEN` со значением этого токена.
4. Запусти вручную workflow **Fetch SPbGASU schedule and hand off to GitHub**.
5. Проверь, что GitVerse получил расписание, GitHub workflow
   **Send schedule received from GitVerse** завершился успешно, а в Telegram появилась
   одна карточка.

GitVerse не получает токен Telegram. GitHub не получает доступ к сайту СПбГАСУ:
между площадками передаётся только проверенный двухнедельный снимок общедоступного
расписания, включая опубликованные вузом ФИО преподавателей. GitHub хранит в своём
служебном CI-cache предыдущий снимок, ID закреплённого календаря, маркеры напоминаний
и дату последнего вечернего обзора. Новые даты за пределами предыдущего снимка считаются
публикацией следующей недели, а не изменением.

Оформление использует Telegram Rich Message: две раскрываемые недели, внутри — дни и
компактные двухколоночные таблицы «Время / Пара». Предмет, тип, аудитория, корпус,
подгруппа и полное доступное ФИО складываются в одну гибкую ячейку, поэтому таблица не
требует широкой трёхколоночной раскладки на телефоне. Текущая неделя и сегодняшний день
открыты по умолчанию, свободные дни собраны в одну строку. Ссылка на сайт СПбГАСУ убрана;
для `.ics` используется нативная кнопка «Добавить в календарь». Если Telegram временно
не примет Rich Message, бот автоматически использует обычную HTML-карточку.

Уведомление об изменении — не короткий обрывок поля. Каждая затронутая пара является
отдельным раскрываемым блоком: сверху видно «было → стало», затем полная актуальная пара
с датой, временем, предметом, типом, местом, преподавателем и подгруппой; прежний вариант
доступен во вложенном раскрытии. Для добавления и отмены также показывается вся пара.

Каждый принятый снимок создаёт `.calendar-output/calendar.ics`, сохраняет его как
семидневный Actions artifact `phone-calendar` и публикует через GitHub Pages по постоянному
адресу <https://volobanov545.github.io/gasu-schedule-bot/calendar.ics>. Это именно подписка,
а не разовый импорт: следующий успешный снимок заменяет файл по тому же URL. Apple Calendar
принимает адрес подписки напрямую; в Google Calendar его добавляют на компьютере через
«Другие календари → Добавить по URL». Частоту чтения определяет сам календарный сервис,
поэтому срочные изменения всё равно дублируются отдельным сообщением Telegram.

Каждый свежий снимок GitVerse одновременно является проверкой напоминаний. Первая пара
напоминается примерно за два часа; за 15 минут до конца текущей пары приходит время,
предмет и место следующей; после последней пары бот молчит. Отдельный GitHub workflow
делает резервную проверку каждые 15 минут с 07:07 до 22:52 МСК с понедельника по
субботу и **обновляет закреплённую карточку даже без положенного уведомления**.
При запоздавшем запуске первая пара напоминается только до её начала, а переход —
только до начала следующей пары, включая перемену. Раньше чем за два часа до первой
пары и за 15 минут до конца текущей уведомления не отправляются.
В карточке раздельно указаны время расчёта статуса и время проверки сайта, поэтому
резервное обновление не выдаёт сохранённый снимок за свежую проверку. Маркерная
заливка `mark` не применяется: акценты сделаны жирным текстом.
Смещение от начала часа снижает вероятность задержки GitHub. Обе дорожки
используют общую concurrency-группу и маркеры в CI-cache, поэтому штатный повтор не
дублирует уведомление.

Если компьютер выключен, публикация всё равно выполняется на GitHub. При недоступности
СПбГАСУ резервный контур пересчитывает время по последнему снимку с его настоящей датой
проверки. CI-провайдеры могут задерживать запуски; интервал 15 минут — заданный график,
а не гарантия доставки секунда в секунду.

Бюджет: 56 запусков GitVerse в учебный день, максимум 1524 запуска за 31 день.
16.09.2026 в кабинете приватного репозитория показано 1941 мин доступного времени;
страница тарифа Free указывает 2000 минут. При обычном запуске до минуты месячный
ритм помещается в эту квоту, но более долгие сборки и ручные прогоны расходуют запас.
Документация лимитов ещё показывает старые 500/1000 минут, поэтому ориентир — кабинет.
Платные дополнительные минуты не подключены.

## Проверенный результат 14.09.2026

Актуальный сквозной запуск: GitVerse `1549957` / job `2998341`, GitHub Actions
`34862127014`. GitHub успешно выполнил оба задания `send` и `deploy-calendar`, Telegram
вернул `message_id=15039`. Публичный URL ответил HTTP 200 с типом `text/calendar` и
содержал 25 событий с 25 опубликованными описаниями преподавателей; шаблон токена и
технический ID приватного чата в файл не попали. Репозиторий переведён в public только
после явного решения владельца; значения Actions/GitVerse secrets остались закрытыми.

## Первый проверенный результат 11.09.2026

Мост прошёл реальную проверку от начала до конца: GitVerse получил публичное расписание,
передал карточку в GitHub Actions, а GitHub отправил её в Telegram. Успешный GitHub run:
`34535663621`; Telegram вернул `message_id=14963`. После изменения сайта старый JSON
endpoint был заменён на текущий Bitrix component action с CSRF-повтором. Безопасный
GitVerse probe `1527788` / job `2942173` распознал 42 занятия группы и реальные даты,
включая 11.09.2026; probe не запускал отправку. Значения секретов в журнал и
документацию не попадали.
